# Практическая работа №3: подготовка к защите

## Что сделано

В карточки товаров добавлены кнопки «Заказать». Каждая кнопка открывает одну
общую форму в `dialog` и передаёт название товара через `data-product`.
Название записывается в скрытое поле `selected-product`.
В форме есть имя, e-mail, телефон, дата, тема, комментарий и согласие.
При ошибках поля подсвечиваются. После успешной проверки окно закрывается,
форма очищается и под подвалом страницы показывается сообщение
«Форма успешно отправлена!». Сервер не подключён.

## Ответы на вопросы для самопроверки

1. **Для чего используется тег `form`?**
   Объединяет поля и кнопки формы. Атрибут `action` задаёт адрес отправки,
   `method` - HTTP-метод. У нас стоит `method="post"`, но JavaScript отменяет
   отправку, потому что серверная часть пока отсутствует.

2. **Чем `label` отличается от `placeholder`?**
   `label` - постоянная подпись поля. `placeholder` - подсказка внутри пустого
   поля, которая исчезает при вводе. Подсказка не заменяет подпись.

3. **Как связать `label` и `input`?**
   Значение `for` у подписи должно совпадать с `id` поля:
   `<label for="order-email">E-mail</label>` и `<input id="order-email">`.
   Нажатие на подпись переводит фокус в поле, а для checkbox переключает флажок.

4. **Для чего нужен атрибут `name` у поля формы?**
   Задаёт ключ, под которым значение попадает в данные формы.
   Например, `name="email"` даёт пару `email=student@example.com`.
   `id` нужен для связи с подписью и поиска элемента, `name` - для данных.

5. **Чем `input type="text"` отличается от `input type="email"`?**
   `text` принимает обычный текст. `email` дополнительно проверяет формат
   адреса и может показывать удобную клавиатуру на телефоне. Он не проверяет,
   существует ли почтовый ящик. Для запрета пустого значения нужен `required`.

6. **Для чего используется `input type="tel"`?**
   Для ввода телефонного номера. На мобильном устройстве обычно открывается
   телефонная клавиатура. Сам тип `tel` не проверяет формат номера,
   поэтому в проекте дополнительно используется `pattern`.

7. **Для чего нужен атрибут `required`?**
   Делает поле обязательным. Текстовое поле нельзя оставить пустым,
   у select нужно выбрать вариант с непустым значением, а checkbox нужно отметить.

8. **Для чего используется `pattern`?**
   Задаёт регулярное выражение, которому должно соответствовать значение поля.
   У нас телефон должен иметь формат `+7 (900) 000-00-00`.
   В выражении `\d{3}` означает три цифры, а `\+` и `\(` обозначают обычные
   символы плюса и открывающей скобки. Сам `pattern` не запрещает пустое поле,
   для этого нужен `required`.

9. **Для чего используется скрытое поле `hidden`?**
   Хранит значение, которое не нужно вводить вручную. У нас это название товара.
   Поле участвует в данных формы благодаря `name`, но не отображается.
   Это не способ защиты: значение видно и можно изменить через DevTools.

10. **Для чего нужен тег `textarea`?**
    Для многострочного текста. В проекте используется для комментария.
    Атрибут `rows="4"` задаёт исходную высоту примерно в четыре строки,
    а не ограничение на количество строк текста.

11. **Для чего используется тег `select`?**
    Создаёт список вариантов, заданных тегами `option`. В проекте пользователь
    выбирает тему заявки: заказ товара, консультация или доставка.

12. **Что делает элемент `dialog`?**
    Обозначает диалоговое окно. Сам по себе тег не открывает его в модальном
    режиме. У нас окно открывается через `showModal()` и закрывается через `close()`.

13. **Чем `showModal()` отличается от обычного отображения блока через CSS?**
    Помещает окно в верхний слой браузера, делает остальную страницу
    недоступной для взаимодействия и переводит фокус внутрь диалога.
    Браузер поддерживает закрытие по Escape и возврат фокуса.
    Обычный `display: block` только показывает элемент и этого поведения не добавляет.

14. **Для чего используется `event.preventDefault()`?**
    Отменяет стандартное действие события. В обработчике `submit` предотвращает
    обычную отправку формы и переход или перезагрузку страницы.
    Проверку и показ сообщения выполняет наш JavaScript.

15. **Что делает метод `checkValidity()`?**
    Проверяет ограничения полей: `required`, `minlength`, тип e-mail и `pattern`.
    Возвращает `true`, если всё корректно, иначе `false`.
    Сам по себе не показывает стандартную всплывающую подсказку браузера.

16. **Что делает метод `reportValidity()`?**
    Проверяет ограничения и, если есть ошибки, показывает стандартное сообщение
    браузера. У нас вызывается после пометки ошибочных полей через `aria-invalid`.

17. **Для чего используется `aria-invalid`?**
    Сообщает программам экранного доступа, что поле содержит ошибку.
    У нас селектор `[aria-invalid="true"]` дополнительно включает красную рамку.
    Сам атрибут не проверяет данные и не запрещает отправку формы.

18. **Почему форма пока не отправляется на backend?**
    Цель практической - изучить форму, модальное окно и клиентскую проверку.
    Серверная обработка и база данных ещё не реализованы. Сообщение об успехе
    демонстрирует прохождение проверки. В будущем данные нужно проверять
    и на сервере, потому что клиентскую проверку можно обойти.

## Дополнительные вопросы по коду

- `defer` позволяет загрузить внешний скрипт параллельно с разбором HTML
  и выполнить его после завершения разбора документа.
- `novalidate` отключает автоматическую проверку при отправке. Оно не отменяет
  отправку и не мешает вручную вызвать `checkValidity()` и `reportValidity()`.
  В методичке назначение этого атрибута сформулировано неточно.
- `type="button"` задаёт обычную кнопку, а `type="submit"` - кнопку отправки.
- `button.dataset.product` читает атрибут `data-product` кнопки.
- `addEventListener()` назначает обработчик события: например, `click` или `submit`.
- `willValidate` показывает, участвует ли поле в проверке ограничений.
  Скрытое поле `hidden` не участвует.
- `reset()` возвращает значения полей к исходным. Это не всегда пустые строки:
  если заданы начальные значения, они восстановятся. Значение скрытого товара
  задаётся при нажатии очередной кнопки «Заказать».
- `::backdrop` оформляет фон за модальным окном.
- `aria-labelledby` связывает диалог с заголовком.

## Что показать преподавателю

1. Открыть сайт и нажать «Заказать» у любого товара.
2. Показать значение скрытого поля выбранного товара в DevTools.
3. Попытаться отправить пустую форму: появятся подсветка и подсказка браузера.
4. Показать ошибку имени из одной буквы, e-mail без `@` и телефона не по шаблону.
5. Ввести `Артём`, `student@example.com`, `+7 (900) 000-00-00`, выбрать тему
   и отметить согласие. Отправить форму и показать сообщение об успехе под подвалом страницы.
6. Открыть форму другого товара: скрытое поле содержит название нового товара.
7. Показать закрытие кнопкой «Закрыть» и клавишей Escape.
8. Открыть HTML, CSS, JS, README, историю коммитов и Pull Request.

## Команды для коммита и отправки

Коммит фиксирует изменения локально. Push отправляет коммиты на GitHub.
Эти команды нужны после новых изменений; выполненная работа уже закоммичена.

```bash
git status
git diff
git add index.html css/style.css js/main.js README.md docs/practice-3-defense.md
git commit -m "feat: add order form modal and validation"
git branch --show-current
git log origin/main..HEAD --oneline
git push -u origin feature/form-modal-validation
```

Команда push выше отправляет именно ветку `feature/form-modal-validation`.
Перед выполнением нужно убедиться, что коммит сделан в ней и в списке нет
необсуждённых изменений. После настройки `-u` из этой ветки достаточно `git push`.
